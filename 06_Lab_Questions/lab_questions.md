# Lab Challenge and Analysis Questions

## Question 1: Alert Triage

### Find an alert where a file was modified. What specific details in the alert tell you what was changed about the file?

I investigated a file modification alert generated by Wazuh.

The alert was:

```text
Rule ID: 550
Level: 7
Description: Integrity checksum changed.
```

The `changed_attributes` section showed:
- `size`
- `mtime`
- `md5`
- `sha1`
- `sha256`

The alert showed that:
* The file size changed from 0 bytes to 2 bytes.
* The modification time changed.
* The MD5 hash changed.
* The SHA-1 hash changed.
* The SHA-256 hash changed.

These details provided evidence that the file had been modified. The before-and-after hash values were especially useful because they confirmed that the content of the file had changed.

## Question 2: False Positive Identification

### Which folders could generate too many FIM alerts to be useful?

Two examples are:

1. `C:\Windows\Temp`
   * This directory frequently contains temporary files created and modified by Windows and installed applications. Monitoring the entire directory could generate a large number of alerts.

2. `C:\Users\<User>\AppData\Local\Temp`
   * Applications, browsers, installers, and other software frequently create and modify files in this directory. Monitoring it could also create significant alert noise.

### Conclusion
Instead of monitoring directories that constantly change, I would focus on sensitive or important directories. Examples include:
* `C:\Users\<User>\Documents`
* `C:\Users\<User>\Desktop`

This would help reduce unnecessary alerts and improve the quality of SOC investigations.

## Question 3: Proactive Defense

### How could Wazuh FIM be used to monitor for ransomware behaviour?

Ransomware often modifies or renames a large number of files. Wazuh FIM could help detect suspicious activity by monitoring important directories and identifying patterns such as:

* Large number of file modifications
* Rapid file changes
* File renaming
* Unusual file extensions
* Changes across many files

For example, if hundreds of files were modified within a short period, this could be investigated as possible ransomware activity. 

FIM alone would not automatically prove that ransomware was present. A SOC analyst would need to correlate the file activity with other security events before determining whether the activity was malicious.

## Question 4: Tool Comparison

### How does Wazuh provide an advantage over relying only on Windows Event Logs?

Windows Event Logs provide useful information about activity occurring on a Windows system. However, Wazuh provides centralized monitoring and security-focused analysis. 

With Wazuh, I can:
* Monitor endpoints from a central location.
* Configure File Integrity Monitoring.
* Detect file changes.
* Generate security alerts.
* View rule IDs and severity levels.
* Investigate file hashes.
* View events through a central dashboard.
* Monitor multiple endpoints.
* Use MITRE ATT&CK mapping for additional context.

During my lab, Wazuh provided detailed information about the modified file, including:
* File Path
* File Size
* Modification Time
* MD5, SHA-1, and SHA-256 Hashes
* Rule ID and Alert Level
* MITRE ATT&CK Mapping

This makes Wazuh useful for centralized SOC monitoring and security investigations.
